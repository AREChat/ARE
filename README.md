# ARE（アレ）— みんなで使えるチャットアプリ

HTML・CSS・JavaScript だけで作った静的サイトを **GitHub Pages** で公開し、データと認証は **Supabase** に置いています。
スマホ（縦向き推奨）・タブレット・パソコンの1つのファイル一式で動きます。**使い方は `help.html`（アプリの「その他」→「📖 操作方法」）を見てください。**

| 広告 | 2027-01-01（日本時間）から（アプリを開いている間）、15秒の映像（AD001〜AD100.mp4）を全画面で流す（chat-ads.js）。**映像は Google ドライブの「広告」フォルダ**に置き、「ファイル保存」の GAS（`docs/file-archive-gas.js` の `doGet`。`?action=list`／`?action=part&id=AD001&i=0`、3MBずつ base64）から受け取る。GAS の URL は `apikey.js` の `adsUrl`（空のときだけ `ads/` の映像を使う）。受け取った映像は端末の Cache Storage（`are-ads`）に残り、つぎの1本を先に受け取っておく。ドライブに「いま入っているもの」だけを流す。タイトル等は `ads/manifest.json`。100本を一巡してから2周目。**出す間隔は区分ごと：家庭・管理者は一切なし／社員・友人は1時間ごと／その他は10分ごと**（サーバーの `ad_free_status` の `interval_min`。画面は区分の名前を受け取らない）。音は最初は消音（🔊で切替）。**はじまって10秒たつと「スキップ ▶」が出る**。**2027年より前に、全員（管理者・家庭の人も）へ 1回だけ「お試し表示」を流す（「見た」はアカウントごとに保存し、`chat-prefsync.js` で端末をまたいで引きつぐ）。管理者は AREShop の「▶ テストの広告を1回だけ出す」か、`chat.html?adtest=1` でいつでも確認できる。**500ポイントで30日間 広告なし（AREShop の最上段・`ad_free_buy`。2027年より前に買うと1月1日から30日。家庭・管理者は買えない）。**サーバーの準備（ad_free_v1／ad_free_v2 の SQL）が入っていない／広告なしか不明／映像が取れないときは、広告を出さない**。映像は sw とプリキャッシュの対象外 |
| 通話 | 1対1のチャットの 📞（音声）・🎥（ビデオ）。着信音・ミュート・カメラ・画面共有（パソコン）。声と映像は WebRTC でブラウザどうしが直接つなぎ、「よびだし」だけを GAS（gas/file-storage.gs の action=call・CacheService）で受けわたす。Supabase は、かけるとき・中継情報をもらうときの本人確認だけ。無料の中継（TURN）は、GAS のスクリプトプロパティ TURN_URLS・TURN_USER・TURN_PASS に入れると自動で使う（chat-call.js）|
| 利用時間レポート | 「🧰 その他」→「📊 利用時間レポート」（`chat-usage.js`）。**ログインしてチャットを使っていた時間**（画面が見えていて、2分以内にさわった間・通話中）を、5分ごと（と画面を閉じるとき）に GAS（`gas/file-storage.gs` の `action=usage`）へ送って記録。Supabase は使わない（本人確認の `report_identity_v1`〔`sql/report_identity_v1.sql`〕を GAS が20分に1回だけ呼ぶ）。**管理者・「家庭」の区分・お試し（ゲスト）は、記録もしない・入口も出さない**（画面とGASの両方で止める）。ランキング（今日／7日／30日／累計）は「家庭」以外の全員。**名前は、管理者には全員本名／ほかの人には、同じグループ（区分）の人だけ本名・ほかのグループは匿名（匿名 A7F3B のような番号）**。区分「その他」は隔離の決まりのため、同じ「その他」どうしでも匿名。**管理者は閲覧のみ**（自分の分は記録されず、ランキングにも出ない）。ごまかし対策：1回に足せるのは「前回から経った時間＋90秒」まで・1日24時間まで。保存先はスクリプトのプロパティ（1人1つ・直近35日と累計）。`usageBackup()` を実行すると、ファイル保存フォルダの月フォルダに CSV の控えを書く。試験：`node tools/usage-gas-test.js`（GAS 本物のコードを Node で）・`NODE_PATH=$(npm root -g) node tools/usage-e2e.js`（ブラウザ） |
| 上のバー | ログアウトは「マイページ」だけ。チャット＝マニュアル・更新・📲（アプリ追加：Android／Windows の Chrome・Edge はワンクリック、iPhone／iPad は「共有→ホーム画面に追加」の案内）、ユーザー＝名前の検索・更新、投稿＝更新、その他＝機能を検索（chat-hdr.js が付け替える）。スマホでキーボードが出ている間は、入力欄を約4行までにして、上のバーを小さくする（body.kb-open） |

### 「押しても反応しない」を作らない仕組み（`guard.js` と `chat-main.js`）

- 機能は**1つずつ別々に起動**します。1つの機能が壊れても、ほかの機能は動きます。
- 起動できなかった機能は、画面の上に「一部の機能は、未実装、または起動に失敗したため使えません：◯◯」と表示し、その機能のボタンを押すと「**現在ご利用いただけません（未実装、またはサーバー側でエラー）**」と表示します。
- Supabase 側の準備がまだない機能（関数・テーブルがない）は、「**この機能は未実装です**」と表示します。
- 処理がつながっていないボタンを押したときも、「この機能は未実装です」と表示します。

## 3. 公開のしかた（GitHub Pages）

1. 上のファイルを、リポジトリの**いちばん上の階層**に置く（フォルダを作らない）。
2. GitHub のリポジトリ → Settings → Pages → 公開するブランチ（`main`）と `/ (root)` を選ぶ。
3. 数分後、`https://（ユーザー名）.github.io/ARE/` で開けます。

## 4. Supabase の設定

1. **接続先**：`apikey.js` に、プロジェクトの URL と公開キー（`sb_publishable_…`）を書く。`service_role` キーは**絶対に書かない**。
2. **データベース**：テーブル・関数・保護ルール（RLS）は、Supabase の「Database → Migrations」に順番に記録されています。別のプロジェクトへ移すときは、その順に実行してください。
3. **Storage**（2026-11-24 から：新しいファイルはすべて Googleドライブ〔GAS「ファイル保存」= `gas/file-storage.gs`〕に置く。`apikey.js` の `videoUploadUrl` が入っていれば、写真・音声・動画・ファイル・投稿・ストーリー・プロフィール写真/動画・ファイル転送〔`file_drop_items`〕・ワークスペース書類・AREShop動画・AI作品はドライブ側。Supabase Storage は URL が空のときの予備と、過去に置いたもの。ドライブ側は自動削除しない）。以下は Supabase 側の設定（保存場所・本番の設定、2026-11-22 時点）：`chat-attachments`（非公開。バケットの設定値は大きいが、Supabase 無料プランの「1ファイル50MBまで」という全体の上限が効くので、実際に直接送れるのは50MBまで。これをこえる動画・ファイルは Googleドライブ側に置いてリンクで送る）、`post-images`（非公開・50MB。動画つき投稿のため sql/post_video_v1.sql で広げた）、`avatars`（公開・2MB）、`file-drop`（本人専用のファイル転送・50MB・7日で自動削除）、`ws-docs`（5MB）、`shop-content`（50MB）。
4. **Edge Functions**（本番に入っているもの・2026-11-22 時点で15個）：`register-user`、`login-user`、`recover-account`、`guest-start`（お試し）、`guest-bye`（お試しのタブを閉じたときの削除）、`clear-push`（ほかの端末の通知を消す）、`change-display-name`、`admin-api`、`admin-delete-user`、`admin-manage-user`、`admin-storage`、`send-push`、`cleanup-stories`（ストーリー整理）、`refresh-info`（天気・電車の更新）、`archive-old-files`（30日たったファイルのドライブ移送）。コードの控えは `edge-functions/`（一部）。**本番に入っているものが正**です。
5. **定期実行（pg_cron）**：拡張機能 `pg_cron` を有効にして登録します。本番は12件（2026-11-22 時点・すべて有効）：`deliver-scheduled-messages`・`deliver-scheduled-content`・`expire-timed-messages`（毎分）、`cleanup-stories-6h`（6時間ごと）、`refresh-info-hourly`・`file-archive-hourly`（毎時）、`live-loc-purge`（15分ごと）、`guest-offline-purge-v1`（5分ごと・10分以上使われないお試しを消す）、`guest-purge-v1`・`purge-memo-trash`・`purge-old-story-archive`（毎日）、`weekly-admin-message`（毎週）。**GitHub Actions や GitHub の Secret は使いません。**
6. **Authentication**：メールの確認や新規登録の設定は、プロジェクトの方針に合わせて確認。パスワードの強さの設定にも、同じ条件（8文字以上・大文字・小文字・数字か記号）を入れておくと二重に守れます。
7. **管理者の登録**：SQL Editor で、管理者にする人の ID を `private.user_roles` に `role = 'admin'` で入れる。

## 5. Googleドライブへの毎日バックアップ

`gas-daily-backup.gs` と「GAS設定手順.md」を使います。前日分の会話とログイン失敗の記録が、ZIPで指定のフォルダに保存されます。**このファイル類は GitHub に置かないでください。**

## 6. セキュリティの考え方

**守りの本体はサーバー側です。** ブラウザの中のコードは、F12（開発者ツール）で誰でも見られ、書き換えられます。これは Web アプリの仕組みで、止める方法はありません（F12 を無効にする細工は、簡単に回避できる上、正しい利用者を困らせるだけなので入れていません）。そのため、「書き換えられても困らない」作りにしています。

| 守るもの | 守りかた |
|---|---|
| 他人の会話・データ | データベースの行ごとの保護（RLS）。自分の会話しか読めない |
| 管理者の操作 | サーバー側で管理者かどうかを毎回確認。画面を細工しても使えない |
| 重要な処理 | 検証つきの関数（RPC）や Edge Function だけが書き込む。直接の書き込みは禁止 |
| パスワード推測 | 5回失敗ごとに、回数と同じ分数だけロック（5回=5分、10回=10分…）。本人と管理者に通知 |
| 入力の悪用 | 長さ・形式の検査、リンクは https のみ、画面への表示は文字として扱う |
| 画面への不正な差し込み（XSS） | 各ページにコンテンツ・セキュリティ・ポリシー（CSP）を設定。外部のスクリプトは `cdn.jsdelivr.net`（バージョン固定）のみ許可 |
| 秘密の情報 | 公開キーだけをブラウザに置く。管理用の鍵はサーバー側のみ |
| 履歴・ログ | 管理者の操作は監査ログに記録。アカウント削除時は、本人の追跡ログも削除 |

**限界（正直な注意）：**
- GitHub Pages は、サーバー側の設定（セキュリティ用のヘッダー）を変えられません。画面の枠への埋め込み対策は、簡易的なものです。より強くするには、Cloudflare などを前に置く方法があります。
- 外部の `supabase-js` は、バージョンを固定していますが、ファイルの改ざん検知（SRI）は未設定です。ファイルを取得できる環境で、ハッシュを計算して追加してください。
- ログインの失敗回数は、「ログインID＋接続元」ごとに数えます。接続元を次々に変える攻撃には、Supabase 側の制限や Cloudflare の併用が有効です。
- 管理者は強い権限を持ちます。管理者アカウントのパスワードは特に厳重に。
- 顔写真の自動撮影は行いません（利用者のプライバシー、法令、悪用のおそれがあるため）。ログイン失敗は、日時・回数だけを記録します。

## 7. 運用メモ

- ログイン失敗の記録：管理者パネルの「セキュリティ」で確認。90日分を保持。
- 復旧コードの再発行・パスワード再設定：本人確認の方法を記録し、本人にマイページで通知されます。
- アカウント削除：申請 → 管理者が承認 → 完全削除。承認のたびに、追跡ログのZIP保存の有無を確認します。
- 個人情報：法令・規約の確認は別途行ってください。

## 8. 動作確認のチェックリスト

- [ ] 新規登録（電話・メールなしで登録できる）、弱いパスワードはエラー
- [ ] ログイン、目のボタン、パスワードを5回間違えるとロックされる
- [ ] 2つのブラウザで、1対1の送受信・既読・編集・削除申請→承認
- [ ] グループの作成、注意事項・リンク・アンケート
- [ ] 画像・動画・PDF・Word・Excel・PowerPoint の送信（日本語のファイル名も）
- [ ] 予約送信（1〜2分後）
- [ ] 返信・転送・リアクション・固定（2つのブラウザで、相手の画面にも反映される）
- [ ] メッセージ検索、ブロック（ブロック中は送れない）、ミュート
- [ ] 入力中の表示、音声メッセージ（録音→送信→相手が再生できる）、スタンプ、@メンション
- [ ] 投稿、フォロー、プロフィール編集
- [ ] ZIP保存（端末にダウンロードされる）
- [ ] 管理者パネル（管理者でだけ表示される）、アカウント作成・編集、削除申請→承認、ZIP保存の確認が出る

## 9. よくあるトラブル

| 症状 | 対処 |
|---|---|
| 「未実装です」と表示される | その機能は起動に失敗しているか、サーバー側の準備がありません。ブラウザの開発者ツールのコンソールに `[ARE feature failed]` と原因が出ます |
| 真っ白・読み込めない | ブラウザの開発者ツールのコンソールを見る。CSP のエラーが出る場合は、`<meta http-equiv="Content-Security-Policy">` の許可先を確認 |
| 「権限がありません」 | RLS／関数の実行権限。新しい関数を作ったら、`service_role` や `authenticated` への実行権限を確認 |
| 予約送信が届かない | `pg_cron` のジョブが登録されているか確認 |
| 通話できない | 試験的な機能。回線によっては不可 |
